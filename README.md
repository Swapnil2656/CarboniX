# 🚀 Carbonix

> **Postman for sustainability APIs** — a mobile-first developer tool that tells you the carbon cost of your cloud infrastructure and exposes it as an open API any developer can build on.

---

## 📌 The Problem

Every time you deploy code to the cloud, servers somewhere in the world consume electricity. That electricity is generated by power plants — coal, gas, nuclear, solar, hydro — and each has a different carbon cost. 

The problem is simple and brutal: **Developers know their AWS bill to the dollar. They have zero idea what their carbon bill is.** 

Cloud providers bury carbon data in annual PDF sustainability reports. It's not queryable. It's not in any dev workflow. Nobody checks it — not because they don't care, but because there's no easy tool to do it.

### 🌍 Why This Exists
- **2–3%** — The ICT sector's share of global CO₂ emissions.
- **~400g** — Average CO₂/kWh in many US-East energy grids.
- **8g** — Approximate CO₂/kWh in Stockholm's low-carbon grid.

There is no "Cost Explorer for Carbon." To estimate emissions today, developers must read PDFs, find external grid intensity datasets, manually estimate compute energy usage, and calculate CO₂ emissions themselves. This process is fragmented, inaccessible, and impossible to integrate into modern CI/CD workflows.

---

## 🎯 Our Solution

**Carbonix** provides programmable sustainability data. It calculates precise cloud instance CO₂ outputs using real grid intensity data, compares regions, and offers actionable optimizations (e.g., *"Switching from us-east-1 to eu-north-1 reduces emissions by 98%"*).

**Target Users:** Developers, DevOps Engineers, and Cloud Architects.

---

## ✨ Key Features

- 📦 **SDK Abstraction:** A pristine, 5-line npm package integration (`npm install carbonix`) that hides complex carbon math.
- 📱 **API Console (Mobile App):** A touch-optimized mobile console to visualize API requests, review raw JSON, and explore deployment optimizations on the go.
- ⚡ **Real-time Carbon Calculation:** Estimates energy (kWh) mapped against real-world geographical grid intensity (gCO₂/kWh).
- 🧠 **Recommendation Engine:** Scans multi-region deployments to produce actionable alternatives (e.g., "Move workload from Virginia to Stockholm to cut emissions footprint").
- 📊 **Interactive Dashboards:** Beautiful visualizations breaking down compute, memory, and storage footprints.

### Our Approach
**Why we chose this problem:** Infrastructure has both a financial cost and a carbon cost, but only one is easily measurable. We built Carbonix to make sustainability programmable.

**Key challenges addressed:** Condensing complex energy math (CPU TDP, Memory, Storage) crossed with global grid data into a simple `calculateCarbon()` SDK call.

**Breakthroughs:** Realizing that the mobile app shouldn't just be an app—it should be a "Postman-style" developer console that validates the underlying SDK's capability.

## 🧪 How to Run the Project locally

### Requirements:
- Node.js ≥ 18
- npm ≥ 10
- Expo CLI

### Local Setup:
This project is built using a monorepo architecture (Turborepo).

```bash
# 1. Install all dependencies across the monorepo
npm install

# 2. Build the shared packages (SDK, Core & Types)
npm run build 

# 3. Start development servers
npm run dev

# Alternatively, run services independently:
npm run dev --workspace=services/api       # Start Backend
npm run dev --workspace=apps/web           # Start Web Dashboard
npm run start --workspace=mobile           # Start Mobile App
```
