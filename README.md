# 🚀 Carbonix

> Postman for sustainability APIs — a mobile-first developer tool that tells you the carbon cost of your cloud infrastructure and exposes it as an open API any developer can build on.

---

## 📌 Problem & Domain

Every time you deploy code to the cloud, servers somewhere in the world consume electricity. That electricity is generated by power plants — coal, gas, nuclear, solar, hydro — and each has a different carbon cost. The problem is simple and brutal: **Developers know their AWS bill to the dollar. They have zero idea what their carbon bill is.** 

Cloud providers bury carbon data in annual PDF sustainability reports. It's not queryable. It's not in any dev workflow. Nobody checks it — not because they don't care, but because there's no easy tool to do it.

## The Gap

Developers know their AWS bill to the cent.  
They have zero idea what their carbon bill is.

Cloud providers publish sustainability metrics in annual PDF reports, but that data is:

- not queryable
- not exposed per instance
- not integrated into developer workflows
- not usable during deployment decisions

Nobody checks infrastructure emissions — not because they don't care, but because there is no developer-first tooling for it.

---

## What Exists Today

### AWS Cost Explorer
Real-time infrastructure billing:

- per service
- per region
- per hour
- fully programmable APIs

Every engineering team tracks cloud cost because the tooling exists.

---

## What's Missing

### Carbon Equivalent

There is no "Cost Explorer for Carbon."

To estimate emissions today, developers must:

1. Read cloud sustainability PDFs
2. Find external grid intensity datasets
3. Manually estimate compute energy usage
4. Calculate CO₂ emissions themselves

The process is fragmented, inaccessible, and impossible to integrate into modern CI/CD workflows.

## 🎯 Objective

**Target Users:** Developers, DevOps Engineers, and Cloud Architects.
**The Pain Point:** The global ICT sector accounts for 2–3% of global CO₂ emissions, yet measuring infrastructure emissions requires manually piecing together complex calculations and tracking down regional energy grids.
**The Value:** Carbonix provides programmable data. It calculates precise cloud instance CO₂ outputs using real grid intensity data, compares regions, and offers actionable optimizations (e.g., "Switching from us-east-1 to eu-north-1 reduces emissions by 98%").

### Your Approach:
- **Why you chose this problem:** Infrastructure has both a financial cost and a carbon cost, but only one is easily measurable. We built Carbonix to make sustainability programmable.

## ✨ Key Features

- ✅ **SDK Abstraction:** A pristine, 5-line npm package integrations (`npm install carbonix`) that hides complex carbon math. 
- ✅ **API Console (Expo App):** A touch-optimized mobile console to visualize API requests, review raw JSON, and explore deployment optimizations.
- ✅ **Real-time Carbon Calculation:** Estimates energy (kWh) mapped against real-world geographical grid intensity (gCO₂/kWh).
- ✅ **Recommendation Engine:** Scans multi-region deployments to produce actionable alternatives (e.g. "Move workload from Virginia to Stockholm to cut emissions footprint").
- ✅ **Interactive Dashboards:** Visualizations breaking down compute, memory, and storage footprints.

## 🧪 How to Run the Project

### Requirements:
- Node.js ≥ 18
- npm ≥ 10
- Expo CLI

### Local Setup:
This project is built using a monorepo architecture (Turborepo).

```bash
# 1. Install all dependencies across the monorepo
npm install

# 2. Build the shared packages (SDK, Core & Types)
npm run build 

# 3. Start development servers
npm run dev

# Alternatively, run services independently:
npm run dev --workspace=services/api       # Start Backend
npm run dev --workspace=apps/web           # Start Web Dashboard
npm run start --workspace=mobile           # Start Mobile App
```
